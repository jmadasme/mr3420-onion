01 — El proyecto

Qué resuelve

Guía y scripts para convertir un TP-Link TL-MR3420 v5 en un servidor onion: recuperación TFTP, instalación de OpenWrt 24.10.8, hardening, Tor v3 persistente, uhttpd en localhost y AP propio.

Problema

El punto de partida

Publicar un servicio desde una red doméstica expone la IP y depende de un port forwarding que casi nadie configura bien.

Solución

La propuesta

OpenWrt en el router, Tor como servicio onion v3 y uhttpd escuchando solo en localhost, con scripts que verifican cada paso.

El concepto

Qué es y por qué existe

Procedimiento y scripts para convertir un TP-Link TL-MR3420 v5 en un servidor onion. Incluye recuperación por TFTP, instalación de OpenWrt 24.10.8 para ramips/mt76x8, endurecimiento del acceso, Tor como servicio v3 persistente, uhttpd escuchando solo en localhost y un punto de acceso propio para administración.

Está pensado para quien quiere publicar una página estática sin abrir puertos ni exponer la IP doméstica, usando hardware de descarte. Importa por el contraste entre la intención y el resultado: los scripts cubren el camino completo, pero la bitácora registra los límites reales del equipo, con 64 MB de RAM, un overlay de 2 MB y un puerto USB que comparte GPIO con un LED.

Lo que no funcionó

Los tropiezos, documentados

Las primeras versiones existen para que estos errores no se repitan: cada una dejó una decisión de diseño verificable.

mr3420-onion-server

Tor no entraba en el overlay

El overlay del MR3420 tiene 2,1 MB y Tor con sus dependencias pedía entre 2710 y 3030 KB. No se forzó opkg con --force-space: se agregaron módulos USB y se armó un extroot ext4 de 4 GB, con lo que Tor y ZeroTier quedaron instalados.

mr3420-onion-server

Puerto USB compartido con el LED de LAN 4

El pendrive no se detectaba porque el puerto USB comparte GPIO con el LED del puerto LAN 4. Se aplicó swconfig sobre el puerto 4, se rehizo el bind de ehci y se creó /etc/init.d/usbpower para repetir la operación en cada arranque.

mr3420-onion-server

Tor terminado por falta de memoria

Con 64 MB de RAM y sin swap, el bootstrap de Tor murió por OOM con un RSS de 16 MB. Quedó pendiente liberar memoria deteniendo uhttpd principal, rpcd y odhcpd, y limitar el consumo del proceso; esa corrección no se llegó a validar.

mr3420-onion-server

Pendrive desconectado y userspace colgado

Una desconexión del pendrive dejó el router con el userspace inoperable. La clave onion se recuperó montando la partición en modo lectura desde la notebook, y la bitácora concluye que el extroot debe migrarse a un disco más confiable antes de retomar el despliegue.

Preguntas típicas

Lo que suelen preguntar

¿Sirve para otro router?

Los conceptos sí; los scripts y el firmware son específicos del MR3420 v5.

¿Es seguro?

Un onion service reduce la exposición, pero no reemplaza el hardening ni las actualizaciones.

¿Dónde está la clave del servicio?

No se publica. Tor la genera en el equipo y queda fuera del repositorio.

¿Puedo volver al firmware original?

Sí, con el script de reversión y el firmware de TP-Link.

¿Necesito una IP fija?

No. Tor establece la conexión saliente.
